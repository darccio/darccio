# T37 De-Cloudflare the website

Make the website buildable, deployable and fully usable without Cloudflare, including search. Keep provider-specific adapters optional and preserve the current site throughout a staged migration. This item queues future work; it changes no hosting, DNS, accounts or public behavior.

**Repository:** site; Zas only for demonstrated generic requirements. **Phase:** Hosting portability. **Depends on:** T02, T22, T23, T24, T29, T31 and a fresh deployed-state audit.

**Status:** Queued. **Subagent:** /root/t37_portability (task planning).

## Evidence and inventory first

- Inventory the current guarded build, deployment artifact and serving behavior before selecting a replacement host or runtime. Record source revision, actual production revision, relevant account configuration, routes and response contracts; distinguish source, preview and deployed evidence.
- Review [T23 PR #43](https://github.com/darccio/darccio/pull/43) and its final merged implementation when available. Its reviewed design packages a public title/summary catalogue into the Pages Worker; this backlog entry does not establish that PR's production deployment.
- Inventory Pages Git integration, preview builds, static-assets binding, generated `_worker.js` and `_routes.json`, `_headers`, redirects, bare/index aliases, trailing-slash handling, MIME types, caching, HTTPS and error/fallback behavior. A homepage fallback with HTTP 200 is not a valid resource response.
- Inventory HTML/Markdown content negotiation, direct Markdown twins, response policy headers and cache isolation; identify which behavior belongs to the site and which is currently supplied by the edge.
- Audit the separate WebFinger Worker and its actual routes/configuration before changing it. Include existing identity verification resources, security.txt, crawler policy and all other well-known endpoints.
- Inventory exact-revision deployment-success checks, post-deploy vanity verification and Standard.site publishing gates. Include project-docs dispatch/update PRs and how their merges cause a deployment; preserve the distinction between a build, a dispatch and a successful production deploy.
- Record external DNS, TLS, proxy/CDN and identity dependencies, including Bluesky handle records and existing DNSSEC/DS state. Document Cloudflare DNS as a separate dependency rather than treating a nameserver transfer as an incidental hosting step.
- Compare provider-independent hosting/runtime options against these evidenced contracts, maintenance burden and cost. Record a decision and reproducible run/deploy procedure; do not choose a service merely to replace one vendor dependency with another undocumented one.

## Portable build and runtime

- Produce deterministic site output through the existing guarded build with a pinned Zas release. Keep normal static pages, feeds, assets and Markdown twins usable on an ordinary HTTP host; distinguish portable artifacts from optional provider configuration.
- Separate site HTTP/search logic from Cloudflare-specific asset access and routing. Provide a documented local/reference runtime and a tested deployment on a non-Cloudflare target, using the same built public-page catalogue and response contracts.
- Preserve search through ordinary GET form submission with no browser JavaScript and no remote search service requirement. Keep Catalan, English and Spanish interfaces, preview-relative links, accessible catalogue/results pages and experimental WebMCP annotations where supported.
- Preserve titles-and-summaries matching, case/accent folding, all-word matching and deterministic ordering; do not silently expand the corpus into article bodies or full-text search. Maintain draft, private, unpublished, CV and repository-documentation exclusions and reviewed project-docs ownership rules.
- Preserve empty/no-result queries, Unicode, query validation/length limits, HTML escaping, GET/HEAD/method handling and safe unavailable-state behavior. Keep HTML and negotiated Markdown results, direct twins, `Vary: Accept`, query `no-store`/`noindex` behavior and removal of stale validators/length headers.
- Keep content-policy/security headers consistent with robots.txt and cache behavior correct across query strings, locales and negotiated representations. Avoid relying on provider defaults to enforce privacy or representation selection.
- Keep site assembly, serving adapters and deployment integrations here. Propose an upstream Zas change only when implementation demonstrates a reusable generator requirement; any such feature remains additive/opt-in and receives its own atomic PR before adoption.

## Migration boundaries

- Scope the core migration to website hosting, runtime and integrations. Cloudflare DNS may remain initially; record that remaining dependency explicitly. A later DNS transfer is a separately planned owner operation, not permission to change registrar, nameservers, DS records, accounts or billing now.
- Preserve all seven vanity routes (`mergo`, `darna`, `cocoon`, `errors`, `xdr`, `awaken`, `x`) and their exact reviewed go-import tuples, including bare/canonical `?go-get=1` behavior. Preserve existing raw-fragment bytes and do not redirect import resolution to an unrelated host.
- Preserve existing URLs/fragments, aliases, canonical URLs, RSS GUIDs, all three feeds, article date precision, Markdown links, microformats, JSON-LD, CV JSON and approved Standard.site identities/backlinks. Retain public email, WebFinger and reciprocal profile/handle verification behavior.
- Preserve source-owned docs, pinned source revisions, untrusted-content/no-plugins protections and rebuild triggers. No deployment may depend on PDS availability; publishing remains separate and requires the exact successful production revision.
- Prepare and verify the target before any cutover. Document owner-required credentials/account actions without committing secrets; this planning item authorizes no migration actions or external notifications.

## Acceptance and verification

- A documented command builds and runs the site locally without a Cloudflare account, APIs or bindings. The same reviewed artifact and portable runtime serve a non-Cloudflare preview, with no undocumented production-only behavior.
- Run meaningful parity checks against the local/reference runtime and target host: route/resource content, MIME, aliases/redirects, policy/cache headers, HTML/Markdown negotiation, error responses and search results. Include no-JavaScript form submission in all three locales, empty/no-result/Unicode/escaping cases and excluded-source/index lifecycle checks.
- Run `make -f .zas/Makefile generate`, `test`, `check-vanity`, microformats and consistency checks. Verify exact live vanity metadata on all seven bare/canonical paths and isolated direct Go module resolution; check before cutover and after every deployment/cutover stage.
- Compare preserved feeds and publishing identities against the recorded baseline; verify real well-known/identity responses rather than status alone. Exercise docs update and exact-revision publishing gates without expanding the approved publication allowlist or making deployment wait for the PDS.
- Confirm independent Datadog monitoring and the GitHub backstop still watch the public domain. Test failure/recovery alerting through the established owner-operated procedure; distinguish configured checks from delivered-alert evidence.
- Record source revision, artifact hash, preview/production target, checks and limits for each stage. Complete only when production is verified on the non-Cloudflare serving path and any retained Cloudflare dependencies are explicitly listed; do not describe a hosting migration as a DNS migration.
