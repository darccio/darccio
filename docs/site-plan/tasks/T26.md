## Implementation

The dependency-free Go bootstrap under `.tools/atproto` defaults to public-read preview. It verifies the pinned account and PDS, exhausts publication pagination, matches canonical root URLs, rejects duplicates and preserves Rizoma. Explicit apply creates a server-keyed TID or merges the sole matching record with CID concurrency protection and unknown fields preserved. A matching record requires no login or mutation.

Account credentials come only from the environment. Ephemeral tokens stay in memory; session cleanup is attempted before public readback and local artifacts, including failed writes and malformed login responses with a parsed refresh token. Errors omit response bodies and transport details. Blind write retries are prohibited: a later discovery run recovers an already-created record.

Verified apply outputs are `.zas/atproto-publication.json` and the exact extensionless `.well-known/site.standard.publication`. No placeholder is included here. The manual, main-only workflow defaults to preview, keeps secrets scoped to its apply step, then runs the guarded build and proposes both outputs in one Git tree/commit. Bot handoff verifies existing proposals, rejects unrelated files, avoids duplicates and explicitly dispatches Site checks. It never commits to main or publishes articles.

The response rule serves the eventual verification file as `text/plain; charset=utf-8`. Site builds remain independent of the PDS and authentication. See [the operating instructions](../../../.tools/atproto/README.md).
