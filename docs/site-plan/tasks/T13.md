# T13 Serve correct feed and well-known headers

Use Cloudflare Pages _headers for actual static feed and well-known files, and Response headers where Pages Functions handle those routes. RSS uses application/rss+xml UTF-8 and max-age 3600; verification/security files use text/plain. Validate actual path-specific bodies.

**Repository:** site. **Phase:** RSS. **Depends on:** T00, T11, T12.

**Status:** Planned. **Subagent:** /root/t13_headers (task review completed; implementation is tracked separately).

## Repository findings

- The owner confirmed Cloudflare Pages with Git integration. No tracked _headers exists; the WebFinger Worker has no ASSETS binding and is unrelated to site delivery. Production build/output settings, static/function routing and fallback rules still need verification.
- Requested feeds and well-known resources currently return 200 text/html homepage fallback. Correcting MIME alone cannot establish that the intended files are served.

## Acceptance

- Every enabled first-party RSS endpoint serves application/rss+xml; charset=utf-8 with Cache-Control max-age=3600.
- Published extensionless verification resources, including site.standard.publication and atproto-did, and security.txt serve text/plain with their actual expected content; missing resources do not masquerade as valid verifiers.

## Verification

- Build with zas generate -full -no-plugins, complete raw vanity copying, and confirm every configured feed and available well-known file survives assembly with exact bytes.
- Use bounded GETs against preview then production; inspect final status, redirect target, Content-Type, Cache-Control and parsed body. Assert RSS XML/root and canonical self URL, and exact path-specific verification text; reject HTML fallback even with status 200.
- Check unrelated HTML, seven vanity imports and WebFinger retain their response behavior; exercise middleware preservation of status, body and unrelated headers.

## Owner and external requirements

- Verify the Pages production branch, build command, output directory, static/function route ownership and fallback rules before activating the prepared Pages configuration.
