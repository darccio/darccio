# T05 Expose dates and metadata in Zas templates

Expose Date and Updated time.Time, Summary, Tags and Canonical without breaking Page access; Updated explicit else tracked git last commit, avoiding build-time fallback. Correct canonical dir/index -> /dir/, standalone .md -> .html URL stays stable. Unit tests and docs; existing output byte-identical by default.

**Repository:** zas. **Phase:** Foundations. **Depends on:** None.

**Status:** [PR #112](https://github.com/darccio/zas/pull/112) merged on 2026-10-11 as f463876; adopted locally in site commit 9bcfd95. **Subagent:** /root/t05_metadata.

## Repository findings

- ZasData exposes Page unchanged; page templates receive earlyPageConfig preview, layouts receive final extracted metadata. Add lazy Date/Updated/Summary/Tags/Canonical methods so both stages agree without eager validation changing existing builds.
- Site uses date_created with quoted dates and unquoted YAML timestamps. T04 must normalize that provenance to explicit date keys; the generic helpers accept time.Time and RFC3339 timestamps with a timezone. Day-only and timezone-free values need a sourced policy before normalization.
- Existing gitCommitDate can find removed/untracked paths with history. Updated must verify current tracking first; no mtime/build-time fallback. Existing sitemap intentionally retains mtime fallback and index.html URLs.

## Acceptance

- Existing Page access and default output remain unchanged; invalid explicit metadata errors only when the corresponding helper is invoked.
- Missing dates return zero time; Updated never invents a time.
