## CV refresh and rendering

The reviewed source remains MAC v0.3. Its English profile, 23 professional/civic
roles, seven retained projects, 15 qualifications/credentials, 58 distinct skill
names and three languages supply the HTML resume. The update uses the owner's
[Sifa profile](https://sifa.id/p/dario.cat) and supplied LinkedIn export; the PDF
and extracted text are not committed. [CV maintenance](../../../CV/README.md)
records reconciled dates, historical AWS validity and the precision convention.

`.zas/resume.yml` explicitly enables the local renderer. Absent that manifest,
the renderer and independent validator do not open CV data; the existing static
JSON-copy behavior remains. The generated source
is HTML with template execution disabled and no Markdown companion. The shared
layout supplies navigation, canonical metadata and the existing Person graph;
the resume adds a contact h-card, role and education events, skills and languages.
Its public contact remains `cc@dario.cat`, alongside LinkedIn and Sifa.

MAC stores full dates, while the HTML displays the source's month/year or year
precision. The lowercase `/cv/` route is the only authorized CV HTML exception;
other CV HTML remains rejected before reading. The raw JSON bytes are preserved
in output, and CV content remains outside all publishing and agent-corpus
allowlists. No new client JavaScript or generator feature is required.
