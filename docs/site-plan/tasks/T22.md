# T22 Negotiate Markdown at the actual site host

**Repository:** site. **Phase:** Agents. **Depends on:** T00, T21, T13, T02, T10.

**Status:** Ready for owner merge in site PR #7; local and exact-SHA Cloudflare preview acceptance passed. Production acceptance follows the owner's merge. **Subagents:** /root/t22_http_adapter, /root/t22_build_adapter, /root/t22_host_review.

## Implementation

The owner confirmed Pages Git integration, production main, `make -f .zas/Makefile publish` and `.zas/deploy`. The guarded build now generates Pages' supported advanced-mode `_worker.js` and `_routes.json` when `site.markdown_negotiation: true`. Pages supplies `ASSETS` automatically; no new dashboard configuration or deployment workflow is needed. The existing WebFinger Worker stays separate.

The final-byte inventory contains only deployed public HTML pages and real rendered Markdown twins. Homepage and draft entries have no invented twins. Raw imports, CV and private/operational paths are excluded before content reads. Direct static assets and all three aliases of the seven raw landing pages bypass Worker execution. Exact landing-page exclusions leave future nested documentation eligible; routing rules are deterministic and stay within Pages' published limits. Existing URLs, HTML and Markdown bytes remain stable.

The server adapter fetches the original asset route first to retain native redirects and errors. GET/HEAD negotiation applies only to known page routes, and any go-get parameter bypasses it. Positive effective Markdown quality must strictly exceed HTML; acceptable ties and absent headers select HTML. Specific exclusions, wildcard precedence, parameters and malformed weights are tested. A fetched companion must match the build digest, so missing-file homepage fallback cannot become Markdown. Unavailable Markdown falls back only to acceptable HTML, otherwise 406. HEAD returns the corresponding status/headers without a body.

Negotiated responses merge Vary: Accept and use separate weak representation ETags, with conditionals evaluated after selection. Date-only validators and ranges cannot cross variants; direct assets keep native behavior. Shared/browser variant storage is disabled with explicit no-store headers because Cloudflare does not generally key its CDN on Vary. All adapter responses retain the robots-aligned Content-Signal, including redirects, errors and 304s. Existing _headers cover bypassed resources. No client JavaScript is added.
