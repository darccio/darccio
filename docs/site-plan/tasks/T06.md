# T06 List pages in Zas templates

Optional Pages(section) metadata pre-pass sorted date descending stable URL tie-break, Title/URL/Date/Language/Summary, published only; concurrency and incremental safety; migration archives optional and off-site entries preserved.

**Repository:** zas. **Phase:** Foundations. **Depends on:** T05.

**Status:** Optional and deferred. **Subagent:** /root/t06_listing (task review completed; implementation is tracked separately).

## Repository findings

- Run starts bounded concurrent rendering after configuration initialization. Build an immutable source metadata snapshot before walk; never append listings from render goroutines or claimedOutputs, which includes only changed files.
- The existing sitemap collector walks finished deploy HTML after rendering. It covers unchanged output, but cannot populate templates beforehand; sitemap lastmod is also unsuitable as publication Date.
- sourceIsNewer has no listing dependency. Incremental additions, deletion, metadata changes and publish:false transitions must invalidate listing consumers. Existing publish:false output can remain stale incrementally.
- posts/index.md curates multilingual posts, Rizoma entries and two off-site links; a simple posts-directory listing cannot replace it faithfully.

## Acceptance

- Listings contain all eligible published pages independently of render scheduling and build mode.
- Disabled defaults preserve existing output; publication dates and URLs follow T05 without invented timestamps.

## Verification

- go test ./... and go test -race ./... in the isolated Zas checkout.
- Fixture full-versus-incremental equality after create/delete/rename/date/language/summary/publish changes; repeated concurrent builds produce deterministic order.
- Cover unknown/equal dates, HTML/Markdown title extraction, malformed metadata, path boundaries and escaping in generated listings; metadata scanning must never execute plugins.
- Confirm opt-out sites retain byte-identical output; optional archive migration preserves every existing local and external entry.

## Commits and operational actions

Each Git commit includes the implementation, its necessary tests and its documentation. Zas commits become focused PRs against current upstream master. External project source changes require their own authorized repository work; preparation artifacts belong in the site repository.

- **zas** · `feat(templates): add opt-in published page listings`: Dedicated upstream PR: expose Pages(section) with Title/URL/Date/Language/Summary using T05 parsing and URL rules; freeze snapshots before rendering, reuse source exclusions and language precedence, exclude publish:false and section index pages, match directory boundaries, sort dates descending then URL ascending, put unknown dates last, and invalidate listing consumers correctly. Include implementation, race/incremental fixtures and API documentation.
- **site** · `feat(archive): render local articles from page metadata`: Optional independent migration after the helper ships: explicitly preserve curated external links, Rizoma and cross-language entries, existing selections, grouping and trailing-slash URLs.

## Rollback

Disable listings and restore the curated archive; revert the dedicated helper PR, then regenerate full without plugins.

## Implementation notes

- Do not repurpose sitemap's finished-output collector or infer publication from filesystem modification time. Define metadata from static source configuration; document unsupported template-generated metadata rather than executing templates during the prepass.
- Conservative invalidation of all opted-in pages is acceptable initially if consumer tracking would add disproportionate complexity.
